## 1. Outcome

**Objective:** turn the demo-grade API into the surfaces the 23/10 deliverable needs — an in-app dashboard, an ingest path that survives realistic file sizes, a CO₂/KPI report with industry-standard metric definitions, and a solver benchmark that scores against public instance sets — without breaking the frozen contract, the honesty labels, or the 526-test baseline.

**Why now:** the in-app dashboard + "enterprise data → app" + "measure CO₂ reduced" workstreams are the current deliverable (dashboard deadline 23/10); the evidence audit (`CLAIM_AUDIT_VA_NGUON_DU_LIEU_2026-10-18.md`) shows the numbers only become defensible if the metric dictionary and the benchmark are standards-based rather than invented.

**Base:** `so2026` @ `d48d7a1` (working tree carries the two 2026-10-18 audit/briefing docs, uncommitted).

**Stack decision (recorded in `EcoMiles Dashboard Stack`):** FastAPI (single source of numbers) → DuckDB 1.5.6 reading SQLite in place → Apache ECharts vendored locally inside the existing Jinja2 page → WeasyPrint for PDF. No Power BI (Windows-only desktop), no Metabase/Superset (second auth surface for a demo-auth build).

## 4. Frozen interfaces (workers build against this; no key may be invented)

### 4.1 Metric dictionary (pure functions in `analytics/metrics.py`)

| Metric | Formula | Standard |
|---|---|---|
| `empty_running_pct` | empty vehicle-km ÷ total vehicle-km | Eurostat road-freight indicator |
| `payload_utilisation_pct` | kg delivered ÷ capacity_kg of used vehicles | fleet-utilisation metric |
| `vehicle_fill_pct` | stops per vehicle ÷ stops of the fullest vehicle | fleet-utilisation metric |
| `otif_pct` | (delivered and within window_end) ÷ orders | OTIF/DIFOT; SCOR Perfect-Order family |
| `km_per_stop`, `stops_per_hour` | km ÷ stops, stops ÷ route hours | last-mile productivity set |
| `cost_per_order`, `cost_per_km` | cost ÷ orders, cost ÷ km (fuel price env-configurable, default documented) | transport cost metrics |
| `g_co2e_per_tkm` | kg CO₂e × 1000 ÷ (kg payload × km) | **GLEC v3.2 / ISO 14083 functional unit** |
| `g_co2e_per_order` | kg CO₂e × 1000 ÷ orders | derived |
| `kg_co2e_wtw` | TTW × WTW/TTW factor from `emission_factors.json` | boundary must be labelled |

Every metric that cannot be computed from available data returns `null` — never a fabricated default.
